# Play with Ms Ziya — Design

Baseline 2026-11-25. Mengikuti [PRD](prd.md), diterapkan melalui [architecture](architecture.md), dijaga oleh [ai-agents](ai-agents.md).

## Arah visual

Adaptasi [Kids From Home Games](https://games.kidsfromhome.com/): katalog game mudah dipilih, gambar sebagai petunjuk, deskripsi tindakan pendek, dan pengelompokan keterampilan. Audit melalui teks publik memverifikasi pola katalog dan mekanik, bukan warna/font/detail geometrinya. Palet berikut adalah keputusan desain proyek, bukan salinan token situs.

Pembaruan arah disetujui 2026-11-25: anak PAUD **4–6 tahun**, interaksi disederhanakan; **Motion + CSS Modules**, GSAP hanya bila diperlukan. Arahan ini menggantikan pendekatan visual minimalis netral sebelumnya. Mekanik tetap mengikuti PRD.

<!-- ryux-context:start -->
- **Audience**: Anak 4–6 tahun, dengan pendamping bila diperlukan.
- **UI direction**: Biru muda dan pink, rounded/playful, ilustrasi flat ekspresif dari referensi gambar pengguna.
- **Motion direction**: Smooth, bouncy, engaging; respons singkat berbasis tindakan, tanpa overstimulasi.
- **Technology**: Motion + CSS Modules; GSAP hanya untuk kebutuhan khusus yang terukur.
<!-- ryux-context:end -->

Referensi visual primer adalah lampiran pengguna `image.png` (ref `image_d342cc20-9e4a-471d-9c5e-d8a8b6f22140`). Teramati: karakter alam antropomorfik, siluet besar membulat, wajah sederhana, bidang warna flat, latar berlapis bergelombang, gelembung petunjuk putih, serta balok huruf dengan sisi bawah lebih gelap. Ini bukti dari satu gambar, bukan hasil uji pengguna. Adaptasikan tata bahasanya ke biru muda/pink; jangan menyalin tulisan Spanyol, komposisi persis, atau aset tanpa hak penggunaan. Gambar tidak membuktikan perilaku animasi; motion berikut adalah spesifikasi proyek.

Ms Ziya menjadi pendamping konsisten. Identitas utama: balok belajar membulat dan gelembung petunjuk dengan satu karakter ramah. Gunakan bentuk organik besar di tepi latar, area soal bersih di tengah; ilustrasi harus membantu mengenali tugas. Satu tindakan dominan per layar. Energi visual ceria, ritme sederhana, gerak terbatas pada petunjuk dan feedback.

## Tipografi dan layout

Fredoka SemiBold untuk judul, Nunito untuk label/isi, Noto Naskh Arabic untuk teks Arab; host font berlisensi secara lokal dengan fallback sans-serif/serif. Teks Arab mendapat lang dan arah yang benar; jangan membalik seluruh UI karena ada satu karakter Arab. Jalur tracing berupa data vektor yang ditinjau, bukan outline font otomatis.

Body minimal 18 px, tombol 20–24 px, judul layar 28–36 px pada tablet; sesuaikan tanpa teks terpotong. Target sentuh anak minimal 64×64 CSS px; pilihan jawaban dan Mulai disarankan 80×80 px atau lebih, jarak minimal 12 px. Radius tombol/balok 20 px, kartu 28 px, modal 32 px. Gunakan sisi bawah solid 4–6 px lebih gelap untuk affordance balok yang dapat ditekan; dekorasi datar tanpa blur/glow berlebihan.

Ilustrasi: bentuk vektor sederhana, kurva lebar, mata/mulut konsisten, tanpa tekstur rinci atau outline hitam tebal. Maksimal satu karakter pendamping dominan per arena; karakter tidak menutupi target. Aset buatan baru harus mengikuti brief per game, mempunyai provenance/lisensi dan dimensi. Emoji prototipe diganti bertahap dengan satu set ilustrasi konsisten. Jangan membuat latar bergerak saat anak menjawab.

Tablet landscape menjadi fokus, tetapi portrait tetap dapat dipakai. Grid 3 kolom pada layar cukup lebar, turun menjadi 2/1 sesuai ruang. Jangan mengunci skala 1280×720 atau memblokir dengan pesan rotasi. Arena tracing mempertahankan rasio dan memetakan koordinat pointer ke koordinat logis.

## Komponen dan interaksi

- Header: identitas, bahasa ID/EN, audio, fullscreen kanan atas; ikon punya nama aksesibel dan state.
- Kartu game: ilustrasi relevan, judul, instruksi pendek, status tersedia. Jangan tampilkan rating/progres fiktif.
- Intro: contoh tindakan, pilihan kesulitan dan jumlah pemain, tombol Mulai/Start berpanah.
- GameShell: kembali, ulang instruksi, giliran/progres; arena mendapat ruang terbesar.
- Hasil: penyelesaian dan hasil nyata per pemain, Main Lagi dan Beranda.
- Dialog: fokus terkelola, Escape menutup, fokus kembali ke pemicu; konfirmasi keluar jika progres sesi akan hilang.

State wajib: default, hover, focus-visible, pressed, disabled, loading, empty, error, success. Keyboard dapat mengakses navigasi dan game pilihan; sediakan alternatif input untuk drag. Tracing tetap membutuhkan pointer dan keterbatasan ini dijelaskan kepada pendamping.

Navigasi PAUD: tampilkan gambar + label singkat + instruksi suara yang bisa diulang; jangan mensyaratkan membaca. Beranda menonjolkan pilihan game tersedia, bukan profil/streak/statistik. Intro memuat satu contoh tindakan, tiga kesulitan, mode, lalu satu tombol Mulai. Pengaturan pendamping ditempatkan sekunder; tidak ada submenu anak yang kosong. Back/Beranda selalu konsisten, tidak berpindah lokasi antarlayar. Tidak ada hover-only action, timed challenge wajib, atau drag sebagai satu-satunya cara menyusun kata. Mode dua pemain baseline bergiliran pada arena yang sama sesuai PRD.

## Motion dan audio

Motion menjadi library animasi React utama; CSS Modules tetap mengatur layout, token, dan state sederhana. Jangan migrasi ke Tailwind untuk pekerjaan ini. GSAP hanya dipertimbangkan untuk timeline kompleks yang terbukti sulit ditangani Motion; dokumentasikan alasan dan biaya bundle sebelum menambahnya. Jangan mengendalikan properti elemen yang sama melalui CSS animation dan Motion sekaligus. Detail API diverifikasi terhadap dokumentasi resmi saat implementasi.

| Pemicu | Gerak target | Durasi/batas | Reduced motion |
| --- | --- | --- | --- |
| Tekan tombol | Scale 1 → 0,96, sisi bawah turun 2–3 px | 80–120 ms; respons input langsung | Perubahan warna/batas saja |
| Lepas tombol | Spring kembali 1; overshoot maksimal 1,03 | Selesai sekitar 180–280 ms; maksimal satu pantulan | Tanpa spring |
| Masuk layar | Opacity dan translateY maksimal 12 px | 180–250 ms; bukan menunda kontrol | Muncul langsung |
| Jawaban benar | Satu pop pada objek terpilih + pujian | 250–450 ms; satu objek, satu kali | Ikon/teks statis |
| Coba lagi | Highlight slot dan petunjuk | 150–250 ms; tanpa shake keras | Highlight statis |
| Pindah giliran | Label pemain berubah, crossfade | 180–250 ms | Label langsung berubah |
| Sesi selesai | Karakter tersenyum + satu bounce kecil | Maksimal 600 ms; tanpa konfeti layar penuh | Hasil statis |

Angka di atas adalah target desain untuk dituning di perangkat, bukan hasil pengukuran. Gunakan transform/opacity; hindari animasi layout besar, zoom kamera, parallax, flashing dan loop idle. Satu rangkaian feedback utama aktif pada satu waktu. Batalkan saat navigasi/unmount, cegah trigger berulang dari ketukan cepat, dan jangan menunda evaluasi/navigasi hanya demi animasi. Pointermove tracing digambar langsung di Canvas tanpa spring pada garis atau koordinat input. Tidak ada timer game yang bergantung pada durasi animasi.

Hormati prefers-reduced-motion sejak render awal dan perubahan preferensi; semua tugas tetap dapat diselesaikan tanpa gerak. Audio dimulai setelah gesture, bisa diulang/mute, tidak bertumpuk, dan berhenti saat keluar. Musik bukan autoplay wajib. Salah menjawab memberi petunjuk tenang, tanpa sirene atau hukuman waktu. Saat tab tersembunyi hentikan dekorasi dan audio yang tidak diperlukan.

## Pemeriksaan desain

Uji label ID/EN terpanjang, karakter Arab, portrait, zoom, keyboard, suara mati, koneksi lambat, retry, dan indikator giliran. Uji dengan anak dan pendamping untuk memastikan petunjuk dapat dipahami tanpa membaca. Aset referensi tidak boleh disalin tanpa hak penggunaan.
